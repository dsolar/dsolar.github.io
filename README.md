# davidsolar.dev

My personal site: a home page plus two games, **The 31st Franchise** (an NBA expansion draft game) and **The Degenerate Trail** (an Oregon Trail-style game). It's a static site, just files, hosted free on GitHub Pages at the custom domain davidsolar.dev.

## Adding a project

1. Put the project in its own folder at the top of the repo, for example `my-new-thing/index.html`. Its address becomes `davidsolar.dev/my-new-thing/`.
2. Paste the site bar as the first thing inside its `<body>`, and link `bar.css` in its `<head>`. The exact markup is at the top of `assets/bar.css`.
3. Save a screenshot as `assets/covers/my-new-thing.jpg` (4:3, about 1040 x 780). Optional: without one, the home page draws a colored block with the title.
4. Copy a `{ ... }` block in `assets/projects.js`, paste it at the end and fill it in. Every field is explained at the top of that file.

That's it. The home page reads the list, so it never needs editing for a new project. Once there's more than one type of project (say a Tool next to the Games), filter buttons show up on their own.

To keep something off the home page but still reachable by its link, set `hidden: true`. To list something you're still building, set `status: "building"`.

Each new game should also load analytics: put `<script src="../assets/analytics.js" defer></script>` in its `<head>` next to `bar.css`.

## Email: hello@davidsolar.dev

The site links to hello@davidsolar.dev. Cloudflare forwards it to your real inbox, so your personal address never appears on the site. One-time setup:

1. Cloudflare dashboard > davidsolar.dev > **Email** > **Email Routing** > **Get started**.
2. Custom address: `hello`. Destination: your personal email. Save.
3. Cloudflare emails the destination a verification link. Click it.
4. Cloudflare offers to add its email DNS records. Accept (**Add records and enable**). They don't affect the website.

To send a test, email hello@davidsolar.dev from another account. The address is written into the page as `data-user="hello" data-domain="davidsolar.dev"` and assembled by `assets/site.js`, which keeps it away from simple spam bots.

## Analytics

Cloudflare Web Analytics is wired into every page through `assets/analytics.js`, but it stays off until you add your site token:

1. Cloudflare dashboard > **Analytics & Logs** > **Web Analytics** > **Add a site** > `davidsolar.dev` > **Done**.
2. Cloudflare shows a short JS snippet. Copy the value after `"token":`.
3. Paste it between the quotes on the `var TOKEN = "";` line in `assets/analytics.js`, then commit and push.

Visits show up in that same Web Analytics screen within a few minutes. It only counts the live site, never local previews.

## The 404 page

`404.html` is what GitHub Pages shows for any address that doesn't exist. Its header and footer are copies of the home page's, so if you change the nav or footer in `index.html`, make the same change there.

## Adding a private area later

GitHub Pages sites are always public. When you want a private corner (for example `davidsolar.dev/lab/`), the domain is already on Cloudflare, so the usual route is Cloudflare Access (free for small use) in front of that folder, which asks for an email code before showing it. It needs the Cloudflare DNS records switched from gray to orange (proxied), so treat it as its own small project. Keep private things in their own top-level folder so the rule covers one path.

## Guillotine odds: connecting Yahoo

`davidsolar.dev/guillotine/` shows survival odds for the Bastille Day league. It's listed on the home page, but the page itself asks search engines not to index it, since it shows friends' team names. Until Yahoo is connected, `guillotine/data.json` holds numbers entered by hand.

Once connected, a GitHub workflow runs every morning from September through January: it reads the league from Yahoo, saves `guillotine/data.json`, and the site rebuilds. Nothing to do week to week. One-time setup, about 10 minutes on a computer:

1. **Create a Yahoo app.** Signed in to the Yahoo account that's in the league, go to https://developer.yahoo.com/apps/create/. Application Name: `davidsolar guillotine`. Application Type: **Web Application**. Redirect URI: `https://davidsolar.dev/`. Under API Permissions, check **Fantasy Sports** and pick **Read**. Click **Create App**, then keep the page open: you need the **Client ID** and **Client Secret** it shows.
2. **Approve access once.** Open this address with your Client ID pasted in: `https://api.login.yahoo.com/oauth2/request_auth?client_id=YOUR_CLIENT_ID&redirect_uri=https://davidsolar.dev/&response_type=code`. Click **Agree**. You'll land on davidsolar.dev with `?code=...` in the address bar. Copy everything after `code=` (stop at any `&`). The code expires in about 10 minutes, so do step 3 right away.
3. **Trade the code for a long-lasting token.** In PowerShell (built into Windows), paste your three values into the first line and run:
   ```powershell
   $id = "CLIENT_ID"; $secret = "CLIENT_SECRET"; $code = "CODE"
   $auth = [Convert]::ToBase64String([Text.Encoding]::ASCII.GetBytes("${id}:${secret}"))
   $r = Invoke-RestMethod -Method Post -Uri "https://api.login.yahoo.com/oauth2/get_token" -Headers @{ Authorization = "Basic $auth" } -Body @{ grant_type = "authorization_code"; redirect_uri = "https://davidsolar.dev/"; code = $code }
   $r.refresh_token
   ```
   The long string it prints is the refresh token.
4. **Store the three values in GitHub.** Repo > **Settings** > **Secrets and variables** > **Actions** > **New repository secret**, three times: `YAHOO_CLIENT_ID`, `YAHOO_CLIENT_SECRET`, `YAHOO_REFRESH_TOKEN`. Secrets stay private even though the repo is public. Never paste them into a file in the repo.
5. **Run it.** Repo > **Actions** > **Guillotine odds** > **Run workflow**. A minute or two later the page shows live numbers and the sample note is gone.

If a run ever fails with "Yahoo sign-in failed", redo steps 2 to 4 for a fresh refresh token.

How eliminations are found: in each finished week, the lowest score among teams still alive is the one that was cut. The model's settings (how many recent weeks count, how far later weeks lean toward the league average, how much scores swing) are the `DEFAULTS` at the top of `guillotine/sim.js`.

## 1. Verify the domain with GitHub

This proves you own it, so nobody else can point a GitHub site at it.

1. GitHub: your profile picture > **Settings** > **Pages** (left sidebar, under "Code, planning, and automation") > **Add a domain** > `davidsolar.dev`.
2. GitHub shows a TXT record. In Cloudflare: davidsolar.dev > **DNS** > **Records** > **Add record**. Type **TXT**, then copy the Name and Content exactly as GitHub shows them. Save.
3. Back on GitHub, click **Verify**. It can take a few minutes.

## 2. Connect the domain

**First, in GitHub:** repo > **Settings** > **Pages** > **Custom domain** > `davidsolar.dev` > Save. This adds a file named `CNAME` to the repo, so run `git pull` before your next push from a computer.

**Then, in Cloudflare:** DNS > Records. Add these. For every one, click the orange cloud so it turns **gray (DNS only)**. GitHub has to see its own servers to issue your HTTPS certificate.

| Type | Name | Content |
|------|------|---------|
| A | @ | 185.199.108.153 |
| A | @ | 185.199.109.153 |
| A | @ | 185.199.110.153 |
| A | @ | 185.199.111.153 |
| AAAA | @ | 2606:50c0:8000::153 |
| AAAA | @ | 2606:50c0:8001::153 |
| AAAA | @ | 2606:50c0:8002::153 |
| AAAA | @ | 2606:50c0:8003::153 |
| CNAME | www | dsolar.github.io |

If Cloudflare already created records for `@` or `www` (some parked-domain defaults), delete those first.

## 3. Turn on HTTPS

Back in repo > Settings > Pages, wait for **DNS check successful**, then tick **Enforce HTTPS** once it's available. That can take a few minutes or up to 24 hours.

.dev domains only load over HTTPS, so until the certificate is issued, davidsolar.dev shows a privacy warning. That's normal. Wait it out.

## Editing without installing anything

On the repo page, press the **.** key (or change `github.com` to `github.dev` in the address bar). That opens VS Code in your browser, for free. Edit a file, then open **Source Control** in the left bar, write a message and **Commit & Push**. The site updates in about a minute.

github.dev can't run programs, so for rebuilding the game use **Codespaces** instead: repo > **Code** > **Codespaces** > **Create codespace on main**. It's a full editor with a terminal, in the browser. Personal accounts get a free monthly allowance, and with no payment method on file it simply stops when that runs out instead of charging you.

## Setting up your own computer (at home)

All commands are for **PowerShell** on Windows. Copy one block at a time.

```powershell
winget install --id Git.Git -e --source winget --accept-package-agreements --accept-source-agreements
winget install --id Microsoft.VisualStudioCode -e --source winget --accept-package-agreements --accept-source-agreements
winget install --id Python.Python.3.13 -e --source winget --accept-package-agreements --accept-source-agreements
```

Close PowerShell, open a new window, then tell Git who you are (this is your private GitHub email, so your real address never shows up in commits) and download the repo:

```powershell
git config --global user.name "David Solar"
git config --global user.email "84147177+dsolar@users.noreply.github.com"
New-Item -ItemType Directory -Force "$HOME\Projects" | Out-Null
cd "$HOME\Projects"
git clone https://github.com/dsolar/dsolar.github.io.git
cd dsolar.github.io
code .
```

The first time Git talks to GitHub, a browser window opens to sign in. That's Git Credential Manager, and it remembers you after that.

To preview the site, run a tiny local web server and open http://localhost:8000. Press Ctrl+C to stop it.

```powershell
py -m http.server 8000
```

## Making changes

Edit in VS Code, save, then:

```powershell
git pull
git add .
git commit -m "Say what you changed"
git push
```

It's live in about a minute. The repo's **Actions** tab shows each deploy.

**Rebuilding the game** after editing anything in `src/31st-franchise`:

```powershell
py src\31st-franchise\build_site.py
```

If you change the raw data (contracts, ratings), rebuild `data.js` first. Install numpy once, then add `--data`:

```powershell
py -m pip install numpy
py src\31st-franchise\build_site.py --data
```

## Differences from the claude.ai version

Online head-to-head and the shared GM leaderboard run on claude.ai's shared database and sign-in, so they're hidden on this site. Everything else works the same, and each visitor's best season is saved in their own browser. Bringing those features back with a free backend like Supabase is a good next project.

## If something goes wrong

- **"git" or "py" is not recognized:** close and reopen PowerShell after installing.
- **404 after pushing:** wait two minutes, check the Actions tab, and make sure `index.html` is at the top of the repo.
- **Push rejected:** someone (or GitHub, when you set the custom domain) changed the repo. Run `git pull`, then `git push`.
- **Domain shows a privacy warning:** the HTTPS certificate isn't ready yet (step 3), or a Cloudflare record is still orange instead of gray.
