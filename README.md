# davidsolar.dev

A personal passion project, built for fun and for learning: a home page of sports games, simulations, fantasy tools and a social calendar, plus an archive of my ESPN Chalk writing. It's a static site, just files, hosted free on GitHub Pages at the custom domain davidsolar.dev. It stays out of search engines on purpose: every page carries a noindex tag.

## Adding a project

1. Put the project in its own folder at the top of the repo, for example `my-new-thing/index.html`. Its address becomes `davidsolar.dev/my-new-thing/`.
2. Paste the site bar as the first thing inside its `<body>`, and link `bar.css` in its `<head>`. The exact markup is at the top of `assets/bar.css`.
3. Save a screenshot as `assets/covers/my-new-thing.jpg` (4:3, about 1040 x 780). Optional: without one, the home page draws a colored block with the title.
4. Copy a `{ ... }` block in `assets/projects.js`, paste it at the end and fill it in. Every field is explained at the top of that file.

That's it. The home page reads the list, so it never needs editing for a new project. Once there's more than one type of project (say a Tool next to the Games), filter buttons show up on their own.

To keep something off the home page but still reachable by its link, set `hidden: true`. To list something you're still building, set `status: "building"`.

Each new game should also load analytics: put `<script src="../assets/analytics.js" defer></script>` in its `<head>` next to `bar.css`.

The site links to hello@davidsolar.dev. Cloudflare forwards it to your real inbox, so your personal address never appears on the site. One-time setup:

1. Cloudflare dashboard > davidsolar.dev > **Email** > **Email Routing** > **Get started**.
2. Custom address: `hello`. Destination: your personal email. Save.
3. Cloudflare emails the destination a verification link. Click it.
4. Cloudflare offers to add its email DNS records. Accept (**Add records and enable**). They don't affect the website.

To send a test, email hello@davidsolar.dev from another account. The address is written into the page as `data-user="hello" data-domain="davidsolar.dev"` and assembled by `assets/site.js`, which keeps it away from simple spam bots.

## Win Probability: crowd votes

After each call, Win Probability shows how other players called it. The votes live in a free Supabase project. The page uses its publishable key, which is safe in public code because it can only add a vote and read one scenario's totals. One-time setup:

1. Supabase dashboard > the project > **SQL Editor** > **New query**.
2. Paste all of `tools/win_probability_supabase.sql` and click **Run**.

That's it. Until it's set up, the game shows what NFL coaches did in similar spots instead, so nothing breaks. Crowd numbers appear on a scenario once it has 20 votes.

The scenarios themselves (`win-probability/data.js`) are built from a separate data package of nflverse play-by-play and Ben Baldwin's nfl4th model. To add newer games, rebuild that package and run `tools/win_probability_build_bank.py` against it, which rewrites `data.js`.

## Guillotine odds: keeping the data current

`davidsolar.dev/guillotine/` shows survival odds for the Bastille Day league. It's listed on the home page, but the page itself asks search engines not to index it, since it shows friends' team names. It reads `guillotine/data.json`, which can be filled two ways.

**Paste the league pages (works any time).** On Yahoo, copy two pages (select all, copy): the league's main page (League > Overview) and League > Starting Rosters. On GitHub, open `guillotine/paste.txt`, click the pencil, select all, paste the overview, then paste the rosters right after it, and **Commit changes**. The "Guillotine update" workflow turns them into `data.json`, adds player projections from Sleeper, and the page updates a minute or two later. Pasting both into a Claude chat works too. The rosters are optional: without them the page still works, just without roster windows or best-lineup estimates. After the Tuesday night waiver run, also paste League > Transactions (after the other two): it carries every bid on each claim, winners and losers, which fills in the Waivers tab under Last week and the Estate line on each fallen team's card. Claims from earlier pastes are kept, so pasting it once a week is enough. Once Yahoo is filling `data.json`, the paste is used only when you commit a new one, and the next morning's Yahoo pull takes over again.

Player projections refresh on their own every morning and on Sunday at 12:47pm ET. They come from Sleeper's public feed, rescored with the league's settings (`tools/guillotine_projections.py`).

**Automatic, through Yahoo.** Since mid-2026 Yahoo approves Fantasy API apps by hand: until it does, every request returns "This application is not authorized to perform this action", even with a working sign-in. The "Guillotine update" workflow tries Yahoo first on every run and skips quietly until then. Once Yahoo answers, it reads the standings, weekly scores, FAB, eliminations and every surviving team's lineup (game times come from ESPN's public scoreboard), so no more pasting.

Yahoo approved the application on Oct 16, 2026. Its approval email has three steps, and an existing app doesn't pick up the permission, so it takes a new one:

- Sign the API Access and Use Agreement in the DocuSign envelope.
- Create a new app (step 1 below, named `davidsolar guillotine 2`).
- Send the new app's Client ID, your name and email on the Developer Application Confirmation Form linked in the email. List every email you've used with Yahoo in its notes field.

Then do steps 2 to 5 below with the new app's Client ID and Secret. They work before Yahoo turns access on: the sign-in succeeds and each run reports "Yahoo hasn't approved this app" until access is on, then the first run after that pulls the league by itself. You'll know it's on when the "Yahoo hasn't approved" note under the page's Updated line disappears.

The sign-in setup (done in Oct 2026 for the first app, `davidsolar guillotine`, App ID 8zS5heCv, and redone for the new app, `davidsolar guillotine 2`, App ID anjKvxxp):

1. **Create a Yahoo app.** Signed in to the Yahoo account that's in the league, go to https://developer.yahoo.com/apps/create/. Application Name: `davidsolar guillotine 2` (any name works). Application Type: **Web Application**. Redirect URI: `https://davidsolar.dev/`. Under API Permissions, check **Fantasy Sports** and pick **Read**. Click **Create App**, then keep the page open: you need the **Client ID** and **Client Secret** it shows.
2. **Approve access once.** Open this address with your Client ID pasted in: `https://api.login.yahoo.com/oauth2/request_auth?client_id=YOUR_CLIENT_ID&redirect_uri=https://davidsolar.dev/&response_type=code`. Click **Agree**. You'll land on davidsolar.dev with `?code=...` in the address bar. Copy everything after `code=` (stop at any `&`). The code expires in about 10 minutes, so do step 3 right away.
3. **Trade the code for a long-lasting token.** In PowerShell (built into Windows), paste your three values into the first line and run:
   ```powershell
   $id = "CLIENT_ID"; $secret = "CLIENT_SECRET"; $code = "CODE"
   $auth = [Convert]::ToBase64String([Text.Encoding]::ASCII.GetBytes("${id}:${secret}"))
   $r = Invoke-RestMethod -Method Post -Uri "https://api.login.yahoo.com/oauth2/get_token" -Headers @{ Authorization = "Basic $auth" } -Body @{ grant_type = "authorization_code"; redirect_uri = "https://davidsolar.dev/"; code = $code }
   $r.refresh_token
   ```
   The long string it prints is the refresh token.
4. **Store the three values in GitHub.** Repo > **Settings** > **Secrets and variables** > **Actions**. Update `YAHOO_CLIENT_ID`, `YAHOO_CLIENT_SECRET` and `YAHOO_REFRESH_TOKEN` (pencil icon next to each), or add any that are missing with **New repository secret**. Secrets stay private even though the repo is public. Never paste them into a file in the repo.
5. **Run it.** Repo > **Actions** > **Guillotine update** > **Run workflow**. A minute or two later the page shows Yahoo's numbers and the "Yahoo hasn't approved" note under the Updated line is gone.

If a run ever fails with "Yahoo sign-in failed", redo steps 2 to 4 for a fresh refresh token.

**Roster freshness.** NFL live scoring does not update Yahoo ownership or lineup slots. The page labels the roster snapshot separately from projection and live-score timestamps, and checks for a newly published roster file while it stays open. Screenshot corrections verify only the named starting lineups; unseen benches and other teams retain their earlier snapshot. A complete roster-only paste can replace all starting lineups, benches and IR. Because its final-game flags may be newer than the saved standings, team totals are reconstructed from those starters’ completed-game statistics (with exact Yahoo screenshot points taking priority); the page identifies that source and uses player projections for the remaining games. A successful scheduled run can still contain a rejected Yahoo import: check the Yahoo step for HTTP 403. Only a successful authorized Yahoo pull provides automatic roster and transaction updates.

**Live scoring.** During games the page checks live scoring every minute and reruns the odds: each starter's points so far are banked and his projection counts only for the part of his game still to play. The scores come from a small relay, `tools/live-relay.js`, that runs free on Cloudflare at https://guillotine-live.dsolar.workers.dev/ (set up Oct 14, 2026). It reads the rosters from `guillotine/data.json`, pulls Sleeper's stats and ESPN's scoreboard (cached ~45 seconds), and returns just the league's players. One-time setup:

1. Cloudflare dashboard > **Workers & Pages** > **Create** > **Create Worker**. Name it `guillotine-live` > **Deploy**.
2. **Edit code**, select everything, paste in the contents of `tools/live-relay.js`, **Deploy**.
3. Check it: open the worker's address (shown on its overview page) in a browser. You should see a short JSON answer with `"games"` in it.
4. Optional: a custom domain such as live.davidsolar.dev (worker **Settings** > **Domains & Routes**). If you add one, update `live_url` in `guillotine/league.json`.

The page looks for the relay at `live_url` in `guillotine/league.json`. If it can't reach it, it tries the feeds directly, and if that fails too it just keeps its last numbers. Free plan: 100,000 requests a day, far more than a league's worth of open phones.

**Managers and send-offs** live in `guillotine/league.json`, which the Yahoo pull never touches. Manager names there override Yahoo's nicknames (some managers hide theirs). This file is public, so never put email addresses in it.

To add a week's send-off from the league email: save the image as `guillotine/eulogies/2026-wk5-beast-mode-samuel.jpg` (about 1200px wide is plenty), then add an entry under `"eulogies"` keyed by the team name exactly as Yahoo shows it:

```json
"Beast Mode Samuel": {
  "image": "eulogies/2026-wk5-beast-mode-samuel.jpg",
  "alt": "One line on what the image shows",
  "haiku": ["first line", "second line", "third line"]
}
```

Clicking that team in The Fallen then opens the image and haiku. Or send the image and haiku to Claude and have it add them.

Empty starting spots: when a lineup has an empty spot, the odds assume the manager fills it with the best healthy bench player who can play it, and add that player's projection to Yahoo's. The roster window shows that player in the spot with an asterisk. With no lineup set at all, the odds use the roster's best lineup, also asterisked. Whether Yahoo has approved the direct connection shows under the page's "Updated" line (from `guillotine/yahoo.json`, which the daily Yahoo check keeps current).

How eliminations are found: in each finished week, the lowest score among teams still alive is the one that was cut. The model's settings (how many recent weeks count, how far later weeks lean toward the league average, how much scores swing) are the `DEFAULTS` at the top of `guillotine/sim.js`.

## Night Out: the social calendar

`davidsolar.dev/calendar/` is our social calendar: shows, comics, games, movies and restaurants around Boston, plus road trips for the bands we love. Friends add their own plans (a dinner, a game-watch, anything), and mark Interested or Going on anything on it. It's on the home page but marked `noindex` (see below). The shows and games come from `calendar/events.json`, which the "Calendar update" workflow rebuilds every morning at 6:41am ET and whenever these files change:

- `calendar/taste.json`: who and what to watch for. Bands we **love** (shown anywhere within `road_trip_hours` of Boston), **big** bands like Pearl Jam (arena and stadium acts, also shown within the road-trip radius), bands we **like** and favorite **comedians** (flagged around Boston), the teams (home games only), the big rooms, and the two theaters (AMC Boston Common on weeknights, Showcase Legacy Place on weekends). Edit it on GitHub like any file; names match loosely.
- `calendar/places.json`: our restaurant list, the page's "Where to eat" section, in three groups: Near home, In town (every corner of Boston plus Brookline, Cambridge and Somerville, grouped by neighborhood in the order of `areas.boston.towns`) and Up Norf. Each place needs `name`, `area` (`home`, `boston` or `north`), `town` and `cuisine` and `note`; `status` is `loved` for our favorites (they sort first) or `try`. Optional: `spot` (a square or village, like Inman Square), `order` (dishes to get), `good` (tags: Guys night, Date night, Groups, Before a show, Before a game, Outdoor seating, Waterfront, Splurge, Book ahead), `site` and `reserve` links. A Google Maps link is added automatically. Friends rate places they've been 1 to 5 stars (the Top rated tab sorts by the group's average), mark Want to go, or tap "Plan a dinner" to put it on the calendar; "Pick one for us" chooses one at random. The page reads this file directly, so an edit shows up as soon as the site rebuilds.
- `calendar/venues.json`: the big rooms' own calendars (TD Garden, MGM Music Hall, House of Blues, the Wang, the Orpheum, Agganis, Roadrunner, Paradise, Royale, the Sinclair, the Chevalier, Laugh Boston), copied by hand in October 2026. It's a stopgap: once the Ticketmaster and SeatGeek keys are in, those feeds bring the same shows in every morning with real times and ticket links, and duplicates collapse into one. Shows that aren't on our lists only appear under **All shows**.
- `calendar/picks.json`: hand-picked shows (road trips, Wilbur shows, anything the feeds miss) and the movie picks. Each event needs `date`, `title`, `cat` (`music`, `comedy` or `sports`), `venue`, `city`, and optionally `time` ("20:00"), `url`, `sub` (a second line) and `drive_hours`. Each movie needs `title` and `release` ("YYYY-MM-DD"), optionally `by`, `studio` and `why`. A movie shows as playing for six weeks after it opens.

Sources: ESPN's public schedules for the Celtics, Bruins and Patriots (no key needed); Ticketmaster's Discovery API and SeatGeek's API for Boston comedy and music, and for loved and big bands within the road-trip radius (SeatGeek also covers the rooms Ticketmaster doesn't sell, like Roadrunner, Royale and the Sinclair); `venues.json`; and `picks.json`. When two sources list the same show (same day, same room, same headliner), the one with the best ticket link wins, in the order Ticketmaster, SeatGeek, ESPN, picks, venues, and any Interested/Going marks carry over. The calendar looks six months ahead.

**SeatGeek key.** The same `SEATGEEK_CLIENT_ID` secret that turns on price alerts (below) also feeds shows into the calendar.

**Turn on Ticketmaster (free, about 5 minutes).** Sign up at https://developer.ticketmaster.com/ > My Apps > copy the **Consumer Key**. Then repo > **Settings** > **Secrets and variables** > **Actions** > **New repository secret**: name `TICKETMASTER_KEY`, value the key. Run **Actions** > **Calendar update** > **Run workflow**. Until then the calendar runs on ESPN plus the hand picks.

**Plans, Interested / Going, ratings.** Friends type a first name once (kept on their phone). Their marks, their restaurant ratings, and any plan they add with **+ Add a plan** or a restaurant's **Plan a dinner**, are shared with everyone on the link through a small vote box, `tools/calendar-votes.js`, running free on Cloudflare. Whoever adds a plan is marked Going, and only they see **Remove plan** on it. Plans drop off a month after their date. One-time setup:

1. Cloudflare dashboard > **Storage & Databases** > **KV** > **Create a namespace**, name it `nightout-votes`.
2. **Workers & Pages** > **Create** > **Create Worker**, name it `calendar-votes` > **Deploy**.
3. **Edit code**, select everything, paste in `tools/calendar-votes.js`, **Deploy**.
4. The worker's **Settings** > **Bindings** > **Add** > **KV namespace**: variable name `VOTES`, namespace `nightout-votes` > **Deploy**.
5. Check it: https://calendar-votes.dsolar.workers.dev/ should show `{"votes":{},"plans":{},"ratings":{}}`.

If you change `tools/calendar-votes.js` later, paste it into the worker again (Edit code > Deploy). The marks and plans already saved stay put.

The page looks for the vote box at `votes_url` in `calendar/taste.json`. Until it answers, marks save on each person's own phone and go up to the shared box the next time it's reachable. Free plan: 100,000 reads and 1,000 writes a day. Anyone with the link can mark things under any name, so keep the link among friends.

**Ticket price alerts.** `tools/calendar_prices.py` runs every 3 hours ("Ticket prices" workflow). It looks up the lowest SeatGeek price for the shows worth watching: bands we love, big shows, bands we like, favorite comics, and anything someone marked Interested or Going. Prices show on the calendar ("From $62", with the drop in green). When a show's lowest price falls at least 10% and $10 below the last alert (or the first price seen), it sends a push notification. To turn it on:

1. **SeatGeek key (free).** Sign in to SeatGeek and open https://seatgeek.com/account/develop (it may forward you to developer.seatgeek.com), create an app, copy its **Client ID**. Add it as a repo secret named `SEATGEEK_CLIENT_ID`.
2. **Phone alerts with ntfy (free, no account).** Install the ntfy app (iPhone or Android). Make up a hard-to-guess topic name such as `nightout-` plus a few random words (anyone who knows it can read the alerts). In the app, tap **+** and subscribe to that topic on ntfy.sh. Add the topic as a repo secret named `NTFY_TOPIC`. Friends who want alerts subscribe to the same topic.
3. **Email too (optional).** Add a repo secret `ALERT_EMAIL` with an address, and ntfy also emails each alert.
4. Run **Actions** > **Ticket prices** > **Run workflow** once. After that it runs on its own.

The drop rule (10% and $10) and how many shows it watches are at the top of `tools/calendar_prices.py`.

## Keeping the site out of search

Every page on the site, the home page included, has `<meta name="robots" content="noindex">` in its head, so search engines can visit but won't list it. (The 31st Franchise gets it from `src/31st-franchise/page.html`, so it survives a rebuild.) Don't block pages in `robots.txt`: a crawler that can't visit a page never sees the noindex tag, and a page that was already listed would stay listed. `robots.txt` blocks only what can't carry a tag: the league send-off images, data files (`*.json`), `guillotine/paste.txt`, and the `tools/` and `src/` folders. Any new page needs the same meta tag. Pages Google listed before drop out as it revisits them, usually within a few weeks; Google Search Console's Removals tool speeds that up.

## Guess the Pick: updating the drafts

The picks come from two free datasets on GitHub: nflverse for the NFL and sumitrodatta's bball-reference-datasets for the NBA. After a new draft (or once a season, so careers and All-Star counts stay current):

1. In `tools/guess_the_pick_build.py`, move `FIRST` and `LAST` up a year so it stays the last 20 drafts.
2. Run `python3 tools/guess_the_pick_build.py`, then `node tools/guess_the_pick_check.js`.
3. If the build lists players "traded in their rookie season", add each one's first team to `NBA_WENT_TO` and run it again.
4. Bump `data.js?v=` in `guess-the-pick/index.html` so phones load the new file.

The NBA dataset doesn't have the 2026 draft yet, so the 2026 first round lives in `tools/guess_the_pick_2026_nba.json`, entered by hand. Once the dataset catches up, the build uses its picks and skips that file's. Later-round picks get in when they made it big (an All-Star, All-NBA, Rookie of the Year or 30+ win shares in the NBA; a Hall of Famer, All-Pro, 3+ Pro Bowls or 60+ approximate value in the NFL). To add someone those rules miss, put "SEASON-OVERALL" in `EXTRA_NBA` or `EXTRA_NFL`.

## Journeyman: updating the careers

Once a season (after the World Series is a good time, when all three leagues have fresh data):

1. `pip install --break-system-packages pyreadr` (once), then `python3 tools/journeyman_fetch.py /tmp/jm` downloads the NBA, NFL and MLB sources (a few minutes).
2. `python3 tools/journeyman_build.py --src /tmp/jm`, then `node tools/journeyman_check.js`.
3. Bump `data.js?v=` in `journeyman/index.html`.

Who's in: careers that ended in 2000 or later, four or more franchises (a team that moved counts once), and enough games to be remembered. Each league keeps its best-known 400; `FLOOR` in the build sets how well known a player has to be, so raise it if names get too obscure. NFL paths start in 1990, so NFL careers that began before then are left out. The MLB data is the Lahman database, which runs a season behind.

## Wipe Yoenis: Yahoo keeper check

The "Wipe Yoenis Yahoo pull" workflow runs Monday mornings from October through March (or by hand from the Actions tab). It saves the 2026 draft, every final roster and every transaction to `tools/yahoo_yoenis/2026.json`, then `tools/yoenis_keeper_check.py` works out each rostered player's 2027 cost from the league rules and compares it with `keepers2027` in `yoenis/data.json`. The result goes in `keeperCheck`, and the 2027 keepers tab shows a line under the list: "all 442 players match", or the players that don't. The check never edits `keepers2027`; fix a flagged player there by hand. The keeper sheet's misspellings ("Junior Camirero", "Ohtani (P)") are matched to that team's keeper picks in the 2026 draft.

A drafted player always costs his 2026 draft round (whoever drafted him, however he moved since), and anyone undrafted costs round 15; drops and waivers don't change that. Run `python3 tools/yoenis_keeper_check.py --dry` to print the report.

## Scouting Report: adding prospects

The quotes live in `tools/scouting_quotes.json`, one entry per prospect: his `id` (Pro Football Reference for the NFL, Basketball Reference for the NBA, the same ids Journeyman's downloads use), `lg`, the exact `quote`, `who` said it, the `outlet`, `when`, the source `url`, and `angle` (`pan` or `glow`). Every quote is real, said before his draft, 25 words or fewer, and checked word for word against the linked page. Never add one from memory. Everything else on the file (draft slot, team, school, size, career numbers, who went later at his position) comes from the data.

1. Add an entry to `tools/scouting_quotes.json`. Trim the quote with "..." at the start or end if it names him or his school; never in the middle.
2. `python3 tools/journeyman_fetch.py /tmp/jm` (skip it if you have a recent download), then `python3 tools/scouting_report_build.py --src /tmp/jm` and `node tools/scouting_report_check.js`.
3. Bump `data.js?v=` in `scouting-report/index.html`.

The stamp works itself out: the experts "whiffed" when they panned a player who turned into a steal or a star, or praised one who busted. Drafts from 2000 to 2021 only, so every career has had time to happen. The daily five walks the whole folder in a seeded order before anyone repeats.

## Wipe Yoenis: trade history

The same Monday workflow pulls every trade since 2013 (`tools/yoenis_trades_pull.py` into `tools/yahoo_yoenis/trades.json`) and `tools/yoenis_trades_build.py` scores them into `tradeHistory` in `yoenis/data.json` for the page's Trades section. Each player counts his season value over replacement (the awards' values, less the 208th hitter's or 160th pitcher's) for the share of the season left after the trade, plus every later season the manager who got him kept him. Within 1.5 is even; vetoed trades are left out. New trades show up after the next Monday run; next season's values fill in once `tools/mlb/<year>.json` has that year.

## Wipe Yoenis: the race

`tools/yoenis_race_pull.py` writes `yoenis/race.json`: every week's head-to-head matchups with each side's 16 category stats and Yahoo's category winners, plus season totals by category. The page's Race section shows each week's matchups (who leads each category and by how much), the standings as they stood after any week (rebuilt from the category results; they match Yahoo's final standings), and every team's rank in each category with how much it needs to pass the team above. The "Wipe Yoenis Yahoo pull" workflow runs it twice a day from April through September. Once the commissioner renews the league and the 2027 draft is done, it switches to the new season by itself (through the old league's "renewed" link).

## Wipe Yoenis: head to head and the waiver wire

`tools/yoenis_history_pull.py` saves every season's weekly matchups (category stats and Yahoo's category winners) and every add and drop to `tools/yahoo_yoenis/history/<year>.json`. Finished seasons are pulled once; the latest is pulled each run. Yahoo refuses some seasons' full transaction list in one call (2023), so it pages through, 100 at a time. `tools/yoenis_history_build.py` turns that into `history` in `yoenis/data.json`: the 16-0 club (and 15-1 near misses), all-time rivalries by manager, and the waiver wire hall of fame, where a pickup counts his value over replacement for the time he stayed on that team plus any seasons that manager kept him. A 16-0 in progress also gets a "16-0 watch" tag on the Race section's matchups.
